## Living helper retirement and exact codec composition

Smallest legitimate live composition: the parent records its actual earned network disengagement/retired-for-departure entitlement; for a living helper, synchronously calls `helper.get_mechanism().cancel("garden_disengaged")` and checks acceptance, then `helper.set_physics_process(false)` before another native tick. Stop the leaf's own process, which otherwise attempts another autonomous cycle after its retry clock. This does not stop the child mechanism's physics; the successfully cancelled child is already inactive and returns without sampling/damage. The parent should run this within its existing nonreentrant mutation, refuse departure on a failed cancellation or unstable post-callback observation, and recheck actual lease/cue closure after synchronous observers. Do not infer a pass merely from a returned boolean.

An executed living helper has actual `status="cancelled"`, `phase="clear"`, positive unchanged HP/capacity, `dead=false`, `death_emitted=false`, exact enabled living collision/layer2/mask1/enemies group, retained original exchange/deadlines/hit/sample history, explicit `last_cancel_reason="garden_disengaged"`, and unchanged source cooldown. Its leaf and mechanism snapshots require a completed paired paused barrier; `_bindings_valid()` and `_live_bindings()` do not require physics processing enabled. Stopping leaf processing therefore introduces no existing native snapshot-access conflict. Inactive samples may legitimately be historical; the codec still requires their original finite start/recovery interval and unchanged cooldown joins. No new snapshot field is needed in the leaf.

Two concrete exceptions matter. First, cancelling before any real cycle leaves native `status="idle"`, `cycle=0`, `phase="clear"`, empty exchange/role/samples/framing and explicit cancellation reason. That is a legitimate closed idle packet, not a cancelled executed packet; never invent a cycle to force a label. Second, a genuinely dead leaf is required to retain `status="cancelled"` and `last_cancel_reason="source_defeated"`. Calling cancel("garden_disengaged") again would overwrite the required death reason and invalidate the leaf packet. Preserve dead leaves without recancellation. Keep actual HP/body/group unchanged for living retirement; fake death, zero HP, disabled living collision, removed enemy group or a made-up cancellation history violate existing lifecycle constraints.

The parent must serialize the separate retired entitlement and actual `helper.is_physics_processing()` join outside the leaf's strict packet, deriving their allowed values from real parent phase/network/route state. Arbitrary saved booleans cannot grant an exit. These parent fields are not additions to `SNAPSHOT_KEYS`. At a quiet whole-parent restore, after pure validation of all saved Hero/parent/Scheduler/leaf state and real recipient bindings, apply each leaf's `apply_validated_state(snapshot)` physical state; restore the actual shared Scheduler with stable owners/floors/actors; call each `restore_mechanism_state(snapshot, bindings)`; then set each leaf's validated processing flag and present the derived parent state without yielding. Re-enabling fresh configured helpers by default would lose retirement; neither leaf restore method serializes or resets processing. No new death, lease request, cue event, HP change, cooldown refresh or departure credit may be fabricated during that commit.

Strict leaf fields (API `act3-root-latcher-2`, schema2): `api_revision,schema_version,stable_id,position,clock_s,resolved_role,hp,max_hp,dead,death_emitted,retry_at_s,collision,mechanism,framing`. Leaf retry is finite within `[0, clock_s+.25]`.
