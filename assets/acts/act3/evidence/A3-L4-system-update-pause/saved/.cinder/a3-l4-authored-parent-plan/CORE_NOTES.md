## Quiet whole-parent order

The following are deliberately separate guarded stages, so the parent can restore its entire world between them:

1. Construct fresh quiet immutable topology (no normal enter/admission/journal earning) and prepare all saved native owner recipes. Validate the **whole** Hero/physical-source/Scheduler/Playback/mechanism/sun/route/progress unit and parent immutable entitlement first.
2. `stage_quiet_restore(unit,saved_player,bindings,paired_scheduler)->bool` repeats the full core pure proof and owns immutable copies/actual refs. This does not mutate a native body; `abort_uncommitted_restore()` is permitted only at this stage.
3. Parent quiet restores actual Hero and all source physical state, invoking `apply_staged_target()->bool` for the target. Target quiet revival/defeat, enabled flags/group and HP/phase commit are native and immediate. Neither provider nor events/deferred writes run.
4. Parent restores its **full Scheduler** with all native lifecycle journals/cooldowns, then all managed Playback cursors. No root-only envelope or source-only Scheduler reset. Call `restore_staged_mechanisms()->bool`; public native Mechanism restore itself reads the actually restored Scheduler and silently rebuilds cues. Both must succeed.
5. `finish_staged_restore()->bool` copies exact control/history, clears cached live proofs, derives actual restored recovery using non-pruning public `source_control_state`, applies checked paused palette, and clears staging. It reconstructs live chosen frames only for genuinely running sources. Admission activation is separate from wire and parent-controlled.
6. Parent quietly commits its remaining route/sun/presentation, performs actual candidate native Camera/HUD whole-unit gate, then independently captures the live unit to compare with saved data before public installation/resume. Quiet commit does not call framing provider as fake authority. `presentation_error()` proves actual target palette; `framing_points_for_context(actualCamera,prospective={})` supplies measured native bounds, not acceptance itself.

Unexpected native commit failure after step3 is a whole-candidate disposal condition; there is no false rollback/partial-success claim. Parent must propagate failure and retire actual held sources while inside Tree. Stage1 can be aborted without physical change. Target/platform topology stays actual; no translated saved body stamp.
