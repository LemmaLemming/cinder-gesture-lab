# Living Forest scene-native kit

Original native-mesh candidate for A3-L2, authored after A3-L1 acceptance. This record covers [living_forest_scenery.gd](../../../scripts/acts/act3/living_forest_scenery.gd) and [forest-leaf-floor.gdshader](forest-leaf-floor.gdshader). It introduces no bitmap, player presentation, attack source, interaction, terrain animation or game clock. The first actual forest strip-scaffold run passed its 46 checks, but its seven portraits exposed missing immense red trunk identity. The scoped art correction below remains unverified until Root reruns the portraits. The existing Root Latcher atlas/component, fixed floor/boundaries/bases and L1 content remain unchanged.

## Native scale, pivots and collision

All meshes use world units, identity local basis and ground-origin pivots; there is no raster scale. `build(room: bool = false)` creates one immutable layout. Calling it again with the same mode is harmless; changing a built mode is rejected by `runtime_error()`.

Every actual collision body has a stable `Solid` child. `blockers()` returns a defensive stable-ID map excluding the floor: `west_boundary`, `east_boundary`, `north_boundary`, `south_boundary`, plus full-only `two_approaches` and `crossing`. `runtime_error()` checks live owned dependencies, fixed local body transforms, native box dimensions, collider identity/settings and the scenic-sun parent relation. The caller still owns the full-level snapshot and scheduler bindings.

## Appearance and public interfaces

The floor shader quantizes native `XZ` sampling to `1/24` world unit and now draws larger muted leaf clusters approximately `1/1.45` world unit apart, with quieter mud patches and fewer occupied cells. Mud RGB ranges from `(0.145,0.125,0.155)` to `(0.172,0.150,0.183)`; larger muted rose/olive leaves lift local contrast around the dark rooted bulb. It uses no `TIME`, vertex displacement, alpha, emission or warning-shaped fills. Its wet leaf impression does not change movement. Faceted flutes/buttresses use opaque unshaded vertex colour; all scenic meshes have normal depth and no cast shadow. Geometry is original code-native production, with no copied bitmap or image edit.

The following trunks now use a dedicated sixteen-side, five-ring folded mesh: alternating radial factors `1/0.58`, ring widths `1.10/1/0.93/0.87/0.80`, and broad light/dark fold facets. Near bark is red `#984654` in white-sun state and violet-red `#774864` in blue-sun state; the farther layer uses `#613c54/#534461`. Existing outside-floor edge-tree mesh, position and material settings remain stable. The sky plane moved by `(0,-10.8,-7.8)`, along the fixed camera's away axis `18Y:13Z`, so its native projected placement is retained while its plane moves behind the roots. This addresses depth with real placement, not a depth-test or render-priority bypass. Native quantization and actual camera translation still require the next graphical check.

- `build(room: bool = false) -> void`: native geometry and fixed collision only. The current separately authored Latcher room is not modified.
- `floor_body: StaticBody3D`: actual floor for public scheduler geometry bindings.
- `blockers() -> Dictionary`: stable IDs to actual fixed collision bodies.
- `show_sun(state: int, stage: String) -> void`: accepts `0/1`, changes quiet floor/bark/sun palette, and lifts the incoming sun during `preview` or `lock`. The caller supplies all state and timing; no local sun timer exists.
- `follow_landmarks(hero_position: Vector3) -> void`: finite hero translation aligns the distant band; it does not move floor, boundaries, bases or edge trees.
- `runtime_error() -> String`: empty means the checked native dependencies remain intact, not gameplay or visual acceptance.

Full mode currently creates seven solid bodies and eighty-eight scenic mesh instances; room mode creates five solid bodies and forty-two scenic mesh instances. Neither mode creates enemy groups, pickups, healing, abilities, contact exits or route progression.

All seven unchanged captures were actually inspected for this correction: [warning](../../../.cinder/root-strip-forest-portraits-shared22/01-warning.png), [lock](../../../.cinder/root-strip-forest-portraits-shared22/02-lock.png), [flank landing](../../../.cinder/root-strip-forest-portraits-shared22/03-flank-landing.png), [active](../../../.cinder/root-strip-forest-portraits-shared22/04-active.png), [recovery](../../../.cinder/root-strip-forest-portraits-shared22/05-recovery-opening.png), [ordinary return](../../../.cinder/root-strip-forest-portraits-shared22/06-ordinary-return.png), [spent](../../../.cinder/root-strip-forest-portraits-shared22/07-spent.png). Observed: hero/source and strip were readable in these poses, but the floor was nearly black, tiny leaf marks dominated the ground, and only slender red-purple column slivers appeared behind the upper HUD beside two sun discs. The offscreen `X=±10.2` trees did not establish visible immense forest scale. G06 and G14 were reopened and inspected against these results.

The corrective values above broaden the actual following columns, deepen their folds, add restrained fused scenic roots and sparse outward shelves, and lift larger quiet leaf clusters. The previous near billboard depth could hide lower portions of distant columns; moving it away while preserving its projected location is a proposed native depth correction. No successful revised render or forward/lateral occlusion result is claimed here. Physical collision geometry, attack timing, camera/controller/cue semantics and source art are untouched.

## Occlusion evidence and required actual checks

Primary technical evidence inspected before authoring: Godot [SpriteBase3D 4.7](https://docs.godotengine.org/en/4.7/classes/class_spritebase3d.html), **AlphaCutMode**, **billboard**, **no_depth_test**, **render_priority**, **pixel_size** and **offset**; [StandardMaterial3D rendering guidance](https://docs.godotengine.org/en/4.7/tutorials/3d/standard_material_3d.html), **Transparency**, **Depth Draw Mode**, **Billboard** and **Render Priority**; exact [4.7.2 Sprite3D implementation](https://github.com/godotengine/godot/blob/4.7.2-stable/scene/3d/sprite_3d.cpp), native quad lines `122–128`, billboard bounds `238–280`, triangle generation `431–477`, item rectangle `894–917`. These establish that alpha discard can avoid transparent sorting while opaque pixels still hide content; render priority does not make depth occlusion safe. This kit therefore separates low physical bases from upper scene meshes and uses no claimed alpha/priority solution. The inspected developer [Sepulvia 2.5D pixel-art breakdown](https://www.indiedb.com/games/sepulvia/tutorials/25d-pixelart), **2.5D definition / Pipeline**, supports a mixed billboard/native-mesh vocabulary with consistent apparent pixel scale; it supplies no forest occlusion proof. No YouTube footage was inspected or retried.

Root must review genuine `339 × 736` portraits with the actual shared Act 3 hero and native Latcher art in both sun states: arrival/each broad court, warning/lock/active/exposed/spent, both approaches around each central base, and the exit view. Every attack source, actual footprint and actual reachable landing must remain visible together. Also check a moving hero close to each lateral limit, background columns/mist/suns across actual camera framing, and the planted base silhouettes against collision. Edge trees may extend beyond the image, but meaningful grounded source/contact silhouettes must fit. An opaque upper or distant mesh hiding the hero requires placement/geometry correction, not a visibility claim based on this record.
