## Exact parent interface and mask ownership

Script: [smoke_bank_visual.gd](../../../scripts/acts/act2/smoke_bank_visual.gd), class `Act2SmokeBankVisual`, extends Node3D, metadata revision `a2-smoke-bank-visual-4`.

- `configure_radius(radius: float) -> bool` accepts finite0<R≤1.05 before construction; rejects later without mutation. It matches the parent's fixed circle and creates no authority.
- `pose(phase: String, normalized_progress: float) -> bool` supports `idle`, `warning`, `lock`, `active`, `recovery`, `clear`, `spent`; malformed/nonfinite input rejects before pose mutation. Finite progress clamps0…1. Every successful pose reconstructs all13 cached transforms/material alphas and invalidates previous wisp masks, including the same phase/progress. The parent must then apply fresh masks.
- `apply_readability(camera: Camera3D, hero_points: Array[Vector3], source_points: Array[Vector3], boundary_points: Array[Vector3]) -> bool` receives the actual current native orthographic camera, actual current Hero quad/feet points, transformed native source-glyph mesh vertices, and **exactly64 ordered actual circle centerline points at the native outline plane**. Parent can obtain the circle boundary from the published CinderCueMesh and transform it through the actual native outline plane; the plain boundary helper is Y0, while the native outline is Y0.025. This asset does not fetch a consumer, scheduler or private cue field.
- Hero/source inputs accept3…512 finite world points with nondegenerate projected convex hulls of at most64 vertices. The boundary must be ordered, convex, distinct, coplanar, and match this immutable source-local radius. Duplicated/disordered outline-triangle vertices are rejected rather than interpreted as a polyline. Source/Hero projection hulls produce conservative rectangles with1.5 native-viewport-pixel padding. The rim band covers projected `CinderAttackFootprint.EDGE_WIDTH/2` (0.0225m on both sides), plus1.5 native pixels, along all64 closed segments.
- Missing/invalid/queued/off-tree/wrong-world/noncurrent/non-orthographic cameras, malformed arrays, behind-camera/outside-viewport points or invalid boundary geometry return false and hide only the upper layer. Base parcels retain the requested phase pose. Camera movement/basis/orthographic projection-scale/offset/clip-plane/viewport changes after the mask call also discard wisps in the shader; the parent must refresh after actual camera movement. This protects stale screen masks without an independent process. Current fixed camera/native execution still needs verification.
- The parent calls `pose` then `apply_readability` after the actual Hero/source pose and current camera, during current presentation/after restore. Idle/warning/lock/clear/spent never show upper wisps even with valid masks. Recovery uses the existing supplied `sqrt(1-smoothstep(progress))` alpha, reaches exactzero at progress1, and hides both layers. There is no extra lifetime or terminal event.
