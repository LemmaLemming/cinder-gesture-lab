## Shared cue and transparency policy inspected

Read [CinderThreatCue](../../../scripts/cues/threat_cue.gd) and [CinderCueMesh](../../../scripts/cues/cue_mesh.gd). The cue supplies the full logical footprint and source marker; it stays depth tested, uses alpha, and places outline/source/fill at Y0.025/Y0.029/Y0.021 with default material draw priority. This asset creates none of those meshes, colours, ticks or rings. Warning and lock share a very light static body rather than an independent action cue.

The owner's [L3 technique notes](../../../data/campaign/act2/levels/A2-L3.md) already record official alpha node-sorting limitations. For the exact local settings, additionally checked official [BaseMaterial3D depth draw/test properties](https://docs.godotengine.org/en/stable/classes/class_basematerial3d.html#enum-basematerial3d-depthdrawmode) and [Material render priority](https://docs.godotengine.org/en/stable/classes/class_material.html#class-material-property-render-priority),9 October2026. Disabled depth writes prevent these transparent surfaces from depositing an occluding depth layer; depth testing remains enabled. Negative material priorities order this transparent pack before default-priority transparent cues. Priority does **not** move transparent objects ahead of the opaque pass, so these settings do not guarantee that the Hero's lowest pixels or other scenery will remain unaffected. Nine low restrained parts are a proposal to validate, not a claim that node sorting has been eliminated.

## Exact parent interface

Script: [smoke_bank_visual.gd](../../../scripts/acts/act2/smoke_bank_visual.gd), class `Act2SmokeBankVisual`, `extends Node3D`.

- `configure_radius(radius: float) -> bool` before construction/addition: accepts finite0<R≤1.05; rejects after construction without mutation. Default is1.05m. This matches the consumer's actual fixed circle and never constructs or changes that authority.
- `pose(phase: String, normalized_progress: float) -> bool`: supports `idle`, `warning`, `lock`, `active`, `recovery`, `clear`, `spent`; rejects unsupported/nonfinite input atomically, clamps finite progress0…1. Calls before ready are stored and applied after the nine parcels are constructed. Parent maps any terminal/cancelled consumer state to `clear`/`spent`; no unpublished consumer schema is assumed.
- Warning/lock are the same faint inactive pose. Active growth reaches the authored envelope by supplied progress0.52 and remains within it. Recovery starts at the full bank and thins to zero alpha/hidden only at supplied progress1. Clear/idle/spent hide all parcels. The actual parent phase/deadline is the sole clock; no auto-removal, completion callback or source-death branch exists.
- `geometry_stats() -> Dictionary` optionally inspects current cached mesh vertices transformed into source-local metres: constructed flag, configured radius, part/material/vertex counts, planar radius/min/maxY, authored ceilings and current phase/progress. It includes hidden parcels, allocates query data only on request and has no proof/transport authority. This helper has not been executed in Godot yet.
- Every pose reconstructs position/scale/Y-yaw/alpha/visibility absolutely from supplied phase/progress. No per-pose resource creation, mesh mutation, signal, local clock, process/physics callback, random state or shader `TIME`. Root can repeat or reverse the supplied progress for paused/fresh quiet presentation without replaying damage or emission.

Root must consume the published finite bank API when available, supply its actual source/clock, and validate actual shared outline/next tell/Hero/clear-floor visibility together in the540×1170 portrait. Source death must stop only future launches while existing banks retain their original lifetime through the parent consumer; this visual cannot enforce or bypass that rule. No player ability or equipment allocation is introduced.
