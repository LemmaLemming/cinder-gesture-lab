## Shared field ownership and dormant binding — exact guard findings

**Two native coordinators sharing one actual field:** structurally allowed by current guards, with disjoint actual source/protocol groups. `SporeRepulsion.bind_environment:64–141` deduplicates fields only in a local `used` map for that binding, retains actual field handles, then connects each coordinator's own `_on_activated` to the same field signal. SporeField has no exclusive consumer ownership. Therefore its two spent IDs/generation/native clock/original deadline remain one genuine supply state across both consumers. Installing a later consumer neither replenishes nor reconfigures that field; recreating/resetting a room-local field would not prove carryover. This is API/source reasoning, not an executed multi-consumer test; cross-consumer neighbor/retreat clearance is still the parent's obligation.

**Dormant C31/C32 cannot bind spores**, even after ordinary Scheduler/Hero binding. `get_spore_response_state:682` declares alive=`not dead and not dormant`; `NativeProtocol.configure:100–102` and `Repulsion.bind_environment:105–109` require alive/unbound/outside callbacks, while `actor.spore_bind_error:688–705` directly rejects dormant and enforces permanent actual consumer identity. A source cannot switch coordinators. The existing one-shot paused restore-recipient constructor is the supported fresh-candidate exposure seam; manual dormant/HP/clock changes are not a substitute. Native binding and actual living activation must occur at legitimate boundaries, not fabricated future-room supplies/actors.
