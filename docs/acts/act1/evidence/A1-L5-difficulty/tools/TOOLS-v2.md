## Runner

`run_a1_l5_difficulty_job.py` launches exactly one explicitly selected case through `python3 scripts/dev/dev.py engine`. It defaults to headless; `--gui` only omits that flag. It has no auto-retry, import, lock cleanup, foreign PID operation or external watchdog. The fixture retains its actual bounded watchdog. A user interrupt is forwarded only to this runner's direct dev.py child and remains an interrupted result.

Invocation shape (parent supplies the actual case/source/hash; this example was not run):

```sh

  --root '/Users/howardchen/.codex/worktrees/campaign-act1/video game idea' \

  -- --case=legacy-producer --report=res://.cinder/l5-legacy-producer01.json
```

There are 69 required base inputs. Paired `.gd.uid` presence/absence is recorded, including the newly introduced fixture UID. Each run banks the runner itself as well as named source report/Store inputs.

Forwarded `--source-report=...`, `--source-store=...`, or another `--source-...-report`/`--source-...-store` path is included automatically. SHA/label selectors are forwarded without misidentifying them as files; the fixture validates their meanings. Other exact literal inputs can be pinned with `--source`. An explicitly requested output `--report` must not already exist and must lie under this checkout's `.cinder`.

Required footer:

```text

```

The report should contain `case`, `checks`, `failures`, `first_failure`, `scope_complete` or `complete`, and `success`. A passed classification requires a unique matching footer and case/report identity, actual terminal exit 0, true completion/success, positive checks/zero failures, empty first failure, unchanged named inputs, and no raw warning/error or interruption/runner error. If both completion keys are present, both must be true. Neither counts alone nor a zero exit alone is a pass. Retain actual `assertions` rows with boolean `passed` and nonempty `label`, one per count; otherwise exact per-assert `PASS:`/`[PASS]` and `FAIL:`/`[FAIL]` stdout rows must agree with counts. Inherited L5 `_expect` prints no passing rows, so the new fixture should retain structured rows. The runner never creates missing assertion evidence.

Raw bytes, native report, source-pre/source-post banks, selected UID/recipe absence, queue observations, closure and first-failure information are retained. Native `elapsed_ms` falls back to inherited `wall_ms`; queue/banner timing is explicitly only observed wall timing. Read-only Git HEAD/branch/scoped status is recorded before launch, at the observed native banner and after closure using `GIT_OPTIONAL_LOCKS=0`; these calls do not mutate Git. Literal API/schema/world declaration lines are attributed to their exact pre-source SHA. They are source attribution, not invented native packet validation.

## Archiver

`archive_a1_l5_difficulty_runs_v2.py --root ROOT --run legacy-producer01` is read-only verification by default. Explicit `--apply` copies only closed selected run trees into `docs/acts/act1/evidence/A1-L5-difficulty/RUN`. Repeat `--run` for a bounded set. `--index-output PATH` creates an optional new selection index only with `--apply`; existing identical indices are retained and differing ones rejected.

Every original run-tree file is copied byte-exact, including pre/post source banks, raw log, native report, runner receipt, exact packet/Store strings and prior failure diagnostics. Recorded hashes must agree. Existing archives are verified and never overwritten. Closed failed launches, failed/canceled/incomplete jobs and missing/malformed native results keep their original status; no result is upgraded from counts. API declarations, literal native scope, case and source references remain attributed to the original run.

For portrait output, use native `shots: [{path, sha256, ...}]`. Existing actual PNGs are checked and copied byte-exact; missing original pixels are recorded as missing without replacement. Any supplied `personal_review` field is preserved as a recorded claim; the archiver does not inspect pixels or confer visual/gameplay acceptance. Raw report bytes preserve all other witness fields and original paths unchanged. Original paths and portable archive destinations stay distinct.

## Companion-preserving archiver v2

Use `archive_a1_l5_difficulty_runs_v2.py` for the new producer. The original runner and original archiver stay unchanged. For each literal `branches[label].all_original_disk_files[name]`, v2 resolves the original path under the report's actual `.cinder` artifact root, checks exact byte count, SHA256 and hex against the original file, and copies those original bytes into `branches/label/name`. `raw_store` must equal the recorded `campaign.json` entry. The separate actual `branch.json` is preserved only after its parsed content equals the literal branch row. Original and portable paths are recorded in `archive-verification.json` and the optional selection index.

Missing, malformed or mismatched companions produce explicit `archival_errors`, `archival_complete: false` and archiver exit 1. Other verified originals may still be archived. No missing bytes are reconstructed from report hex, and recorded gameplay success/failure is never changed. Existing archives and files are never overwritten; a later repair requires a separately chosen archive destination/workflow. A mismatch during copying stops and preserves the partial archive for diagnosis.

Private Python syntax/help and synthetic temporary-file checks covered valid byte copies, retention of an original failed result, verification without overwrite, missing-original rejection and literal-hex mismatch. These were tool checks only; no engine job or actual run archival was performed. The invocation and run selection remain the same as v1.
