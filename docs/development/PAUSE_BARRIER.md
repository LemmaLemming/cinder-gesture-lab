# Native tick pause barrier

`Game.request_pause_deferred() -> bool` is the supported callback pause seam for an aggregate containing several native consumers and later required presentation. Call it from the actual source/cue/hit observer, then capture at a deferred paused boundary. It returns true for the one newly queued request, false for a duplicate or absent live player. `is_pause_requested()` reports the pending request. The recognizer consumes input and clears the old gesture chain immediately; an early Resume cannot discard the request. After the current native tick finishes, one main-thread deferred flush opens the existing preview bench/pause HUD, or routes the production Shell through its existing pause/save operation.

This policy completes the current fixed tick. It does not roll back an already delivered hit, interrupt a half-finished native consumer, add a new tick, advance a deadline, synthesize a sample, move an actor, or heal. Direct `SceneTree.paused = true` inside an early consumer callback can still interrupt later consumers and required presentation; their pure writers reject that incoherent aggregate. Keep the original failed reproduction as evidence and use the supported request in a separate run.

Production Shell operations queued from physics callbacks now freeze at the beginning of their existing deferred drain. Ordinary UI requests outside physics still pause immediately. Queued/draining operations consume recognizer input. Callback checkpoint/completion requests therefore capture after all fixed-tick consumers and parent presentation have finished; durable write failure retains the paused failed operation. Existing exact Retry/Continue, main/side isolation and snapshot schemas are unchanged.

If a queued checkpoint is followed by actual death in that same tick, the Shell records the final fatal active snapshot without replacing the last living checkpoint and stays paused. Public Retry restores that earlier complete living unit with its original resources. The request belongs to the Game/Shell instance; source owners must cancel invalid authored work during transitions rather than treating this pause request as an actor reservation.

A fatal tick still requires the authored parent to settle its required presentation and native children before capture. A parent that returns on `hero.dead` before its required visual update may remain incoherent even with this barrier. The barrier does not reconstruct those poses or grant new health. The shared test's fatal result covers its own parent, which updates actual phase-derived presentation at physics priority200; it does not certify Act1's unfinished Crater Gardens fatal aggregate.

## Targeted evidence and source applicability

The new `python3 scripts/dev/dev.py test pause_barrier` fixture uses the actual production Shell, shared Player, two real LaneMechanism consumers, actual stationary circle, late required mesh presentation, exact JSON and isolated PID-named format2 save files. It tests direct callback rejection, lock/active/recovery deferred capture, duplicate request/input/early Resume consumption, ordinary production request_pause from physics, actual source-hit death/dead Resume, native observer checkpoint, failed durable write, fresh exact native aggregate restore and held pause. Its registry entry and floor are explicitly TEST ONLY; this is no authored-level or portrait acceptance.

First and second runs failed16checks/8 while preparing the fixture; a single-case diagnostic failed2/1. A dictionary dot insertion created a StringName owner ID, correctly rejected by the existing stable-String binding validator. The fixture now inserts the literal String key; no scheduler or stable-ID rule was weakened. Corrected third run passed99/0, and the expanded Resume run passed100/0. Review then found the real checkpoint-followed-by-death defect: the added actual-hit regression failed16/2 against the prior Shell. The corrected complete suite passed **116 checks, 0 failures**, exit0, clean on Godot4.7.2 `ed1daf0bf`. It verifies the fatal active save, unchanged prior living 0.1HP/zero-ammo checkpoint and fresh exact public `request_retry()` restoration. This regression invokes the public Shell method, not a GUI Retry button. Original results and exact available source snapshots are retained in the [portable evidence index](evidence/shared23-native-dependencies/index.json); partial historical provenance is identified rather than reconstructed.

The [Godot4.7 Engine documentation](https://docs.godotengine.org/en/4.7/classes/class_engine.html#class-engine-method-is-in-physics-frame) provides `Engine.is_in_physics_frame()` for the physics-specific drain decision. The installed4.7.2 [SceneTree source](https://github.com/godotengine/godot/blob/ed1daf0bf001b61586d9930840f2f1394092c079/scene/main/scene_tree.cpp) was inspected: physics node processing completes before the main-thread message-queue flush; node processing checks pause eligibility for each node. This explains the observed skipped later consumer under direct midtick pause and motivates the tested deferred policy. Nodes in separate threaded process groups are outside this authored main-thread policy.
