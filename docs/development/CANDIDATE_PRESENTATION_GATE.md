# Candidate presentation gate

Shared34 adds a post-quiet native presentation gate for opted restore candidates. Act1 request `c2ab477d-d2dc-4b7e-a8db-ff1abb5ba3e1` identified that a pure saved-player validator still sees the fresh recipient at spawn; its current body cannot prove saved later-room optics. The supported order measures actual quietly restored Player/local geometry with the saved native camera and real candidate HUD before donor retirement or attempt changes. Native35/0 and directly affected Shell52/0/constructor71/0 are closed; authored A1-L3 adoption, complete art/cue union and level acceptance remain separate obligations.

## Exact order

Shell keeps `_snapshot_problem` as mechanical whole-unit/schema/context prevalidation. The actual restore constructor only builds entitled immutable recipients. Saved-player validation never moves the fresh Player or substitutes a translated body stamp.

After every component validates, `_prepare_snapshot` quietly restores the actual Player, then the level's local units and progression. Only then `_candidate_presentation_error` applies the validated saved `shell.camera_focus + CAMERA_OFFSET` to that candidate's real current Camera3D. It does not change installed Game aliases, the donor camera/HUD, focus, shake, release anchor or resources.

Shell constructs a real canonical GameHUD under a temporary offscreen SubViewport, sized exactly from the installed outer HUD's native visible pixel dimensions. This is the outer 540×1170 layout at that native size, rather than the 270×585 world viewport. Integral dimensions from 1 through 16384 are supported. The HUD retains its actual Script and native Label/autowrap/layout, enters campaign mode, hides its overlay and receives the restored candidate's real HP, shells and actual objective. Its CanvasLayer is hidden, GUI input and rendering are disabled, no campaign observers are connected, and no frame or simulation tick is advanced.

Shell invokes the candidate's presentation wrapper and immediately frees the whole temporary HUD viewport on either result. Any error disposes only the candidate and sets `Restore candidate presentation failed: <diagnostic>`. A successful candidate is returned before `retry_snapshot`, `leave_side`, installation, donor disposal or any progression/disk change. `_install` retains its existing final lifecycle, aim/focus/shake and status ordering.

## Additive APIs

```gdscript
# CinderLevel; RESTORE_PRESENTATION_API_REVISION = level-restore-presentation-1
func restore_candidate_presentation_error(
    framing_camera: Camera3D, framing_hud: GameHUD
) -> String

# Optional pure virtual. Default returns an empty string.
func _restore_candidate_presentation_error(
    framing_camera: Camera3D, framing_hud: GameHUD
) -> String

# Game; existing live and explicit-player APIs remain byte-identical.
func camera_framing_plan_for_context(
    points: Array, desired_focus: Vector3, framed_player: CinderPlayer,
    framing_camera: Camera3D, framing_hud: GameHUD
) -> Dictionary

func camera_framing_error_for_context(
    points: Array, framed_player: CinderPlayer,
    framing_camera: Camera3D, framing_hud: GameHUD
) -> String
```

The wrapper requires a paused, entered, fully quiet-restored nonplayable recipient. It validates ready retained actor/effects/Shell/camera/HUD nodes, the current camera and Player in the candidate's real viewport/world, a Script-free Camera3D and canonical HUD Script with no alternate CanvasLayer viewport. A dedicated busy flag prevents reentrant capture, restore, lifecycle, finish and progression methods during the hook. It rechecks lifecycle/native bindings after a successful hook. The hook is trusted level code and must stay pure: no mutations, signals, yields, admission, damage, future activation or camera fitting. Guards are not a rollback mechanism for a violating hook.

The new Game context views preserve the actual shared camera's fixed basis, orthographic KEEP_WIDTH, width, depth, cull mask, offset and shake margins. They require an actual canonical HUD in the same SceneTree, a Script-free viewport and the exact main outer visible pixel size. The candidate's actual world viewport supplies projection aspect, and the supplied HUD's native fitted objective/status region supplies its safe rectangle. Actual native capsule, full billboard quad and shadow bounds come from the unchanged explicit-player accessor. The plan is a future-fit diagnostic; only the error view checks the current saved-camera projection. Neither licenses a route, LOS, contact or damage. The gate never applies a proposed plan.

## Opt-in validation and capture obligations

An opted level's `_local_snapshot_error_with_player` must still prove the complete saved mechanics and native binding context against the already validated saved Player, while deferring only the optical check that requires quiet-restored native geometry. It must not use fresh spawn art, donor HUD/camera, common-frame translation or a fake accepted stamp to claim that saved-world containment passed.

The actual live Save capture must independently enforce current native presentation before producing a persistable snapshot. A level can keep that check in its capture override before delegating to the base `snapshot_state`. Do not put the only optical guard in `_local_snapshot_error`: that method also runs before the local restore commit, when restored Player geometry can coexist with still-pristine source/cue state. Mechanical validators remain mandatory there; final optical validation belongs in this new hook. Legacy levels with the empty hook retain their existing mechanical behavior and do not acquire a new optical acceptance claim.

The owner supplies the complete actual source/art/cue, footprint, landing and ordinary-primary opportunity union. Required native render parts must still reject missing, hidden or changed bindings according to their supported guards. Actual saved Player basis, presentation/action quad, shadow and restored source state are measured after their real quiet commits. Whole-union containment cannot stand in for occlusion or visual readability.
