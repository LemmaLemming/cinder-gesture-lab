# Binding-tail optimization withdrawn

Root withdraws candidate `4b0f0db6` from production selection. The accepted
Authored source remains `9aed90b7`; runtime remains Shared74. One ordered
original/candidate measurement gives no convincing overall benefit. No repeat
for a clean label or a better timing result is planned.

The candidate changed only two private validated binding-tail paths. Public
fallback validation, native getter order, fresh catalogue checks, exact scalar
comparison and the full post-getter wire check remained. Correctness alone did
not justify keeping the extra implementation.

## Executed checks

The actual correctness pair completed **81 checks, zero failures per cell**.
All 29 ordered observations and the initial exact wire matched. Both phases used
the canonical Script identity. All 86 source slots and original bytes/mode were
restored under the canonical Godot lock. This exercised source-error validation,
not a Playback plan, campaign save or full gameplay route. A live catalogue
mismatch was not exercised.

The cost pair used the unchanged existing 113-check fixture directly. Both
cells completed **113 checks, zero failures**, with the same 72 automatic
advances, one separate manual advance, 15 separate fixed-clock probes, four

## Status and custody

Both pairs remain **Host2/NONCLEAN** because each cell retains the macOS
`get_system_ca_certificates` diagnostic. The correctness host exposes canonical
API return 0 without a separate OS child status. The cost host records canonical
API return 0 and the same actual owned Popen child's return 0 separately; this
is not a second independent external terminal receipt. Native functional results
do not relabel either host as clean.

The cost pair closed both children normally and restored all 123 source slots,
including exact original Authored bytes/mode, under one canonical lock. Root and
the independent reviewer checked the raw profile extraction, original indexes,
source retention, semantic equality and every declared metric. No runtime
candidate is retained.

Cost-host v1 was blocked during source review and never executed: it lacked an
immediate source recheck and could overwrite an unknown edit during restoration.
The additive v2 checks bytes, size, mode and regular-file identity immediately
before replacement. It restores only the known candidate, leaves an already
original file alone, and refuses to overwrite unknown bytes, modes or types.
Fifteen host-only checks cover these cases and owned-child closure. The
cooperating lock does not eliminate an uncooperative external OS race. The
earlier executed correctness pair had no unknown drift; its original records
and verified restoration remain unchanged.

The first inert correctness leaf had an invalid renderer lookup discovered
before execution. It remains unselected and unexecuted. The corrected renderer
observer produced the actual 81-check results; no failed engine result is
invented for the earlier draft.
