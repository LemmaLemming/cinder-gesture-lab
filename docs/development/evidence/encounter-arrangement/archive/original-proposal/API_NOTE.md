# Proposed encounter arrangement API — inert and unused

Root alone may promote `encounter_arrangement.gd.txt` to `scripts/combat/encounter_arrangement.gd` and the focused test to `tests/encounter_arrangement_smoke.gd`. Neither text file has been parsed, imported or executed. No owner/shared production path, registry, ledger, settings or worker chat is changed. The helper alone does not close the stated19 accepted-level Challenge arrangement gap.

A trusted level owner supplies a schema1 definition containing `unit_ids`, retained `recipes` and `current`. Unit IDs are unique existing stable unit identities; a unit may be an entire authored source encounter or an owner-defined attack segment. Every recipe has exactly `recipe_id`, `profile`, `order`. Recipe IDs use `owner-name@vN` with canonical positive integer versions, are globally unique in that definition, and must never be reused for changed content. Every order is a complete unique permutation of the same unit inventory. No subsets, foreign IDs, additional sources or numerical/topological modifications can be described. The exact current map has `assisted`, `standard`, `challenge`; each value names a retained recipe of that same profile. Multiple old versions remain present.

`CinderEncounterArrangement.new(definition)` validates the entire closed shape before deep-copying it. Unsupported keys/types, missing fields/profile mappings, invalid schemas, duplicates, foreign units, unversioned IDs and cross-profile mappings fail through `last_error`; failed selection/restore returns `{}`. Configuration is fixed for that helper instance. `definition()` is a detached copy. Profile names match the existing CinderDifficulty catalogue; the helper never constructs Difficulty, reads a preference/file/world, resolves stats or accesses native IDs.

At a fresh profile boundary only, `select_fresh(profile)` returns a detached `{schema_version:1,profile,recipe_id,order}` descriptor from the current mapping. Persist the whole descriptor with the owner's encounter state. For an active attempt/checkpoint/save, call `saved_error(descriptor)` or `restore(descriptor)` against a trusted definition retaining that historical recipe. Restore requires the exact saved profile/order to match that retained recipe and never consults `current` or a new preference. A changed map affects future selections; deleting or changing an old recipe makes its old save refuse instead of silently remapping it. Integral JSON schema1.0 is accepted through CinderSnapshotCodec's integer convention; restore preserves its representation and never mutates caller inputs.

Definitions are trusted authored data, not authorization certificates. A standalone helper cannot prove historical publication integrity if a caller fabricates both a definition and matching descriptor. Owners must retain immutable recipe source/version history, use actual existing unit IDs and validate their persisted whole-level codec. This helper provides no source/geometry/stat/timing/lease/safety authority, native validation reuse, frame cache, process-priority behavior or gameplay consumer. Owner semantic review must explain the new player decision, integrate actual source/segment ordering, preserve required escapes/attacks/ordinary loadouts and legacy full-level save/Retry behavior. No level is made Challenge-compliant by selecting a different string/order without that work and evidence.

The focused proposed test uses one three-unit authored inventory. It checks fresh profile choices, an old save after current-map/preference change, retained-recipe deletion/content tamper, ordinary JSON integral schema roundtrip, constructor/definition/selection/restore alias isolation and targeted malformed definitions/descriptors without caller mutation. It has no native encounter, timing sample, route, visual, balancing or acceptance credit.

Output lines are exactly `CINDER_ENCOUNTER_ARRANGEMENT_REPORT path=<absolute> sha256=<hex>` and `Encounter arrangement smoke: <N> checks/<F> failures; complete=<true|false>; pure metadata only`.
