# A1-O1 registration runner preparation

This is inert preparation for Integration. No engine, import, parser, test or Git command was run to prepare it. Root must promote the exact owner content, inherited helper, canonical registration fixture and completed-return wire before invocation. Missing promoted resources or named genuine script UIDs fail before queue acquisition and engine start. The selected new registration script UID may be absent before import; it is tracked explicitly and must exist afterward.

Run the phases separately, in this order, through this wrapper:

```sh
python3 .cinder/a1-o1-registration-native/run.py selected-import
python3 .cinder/a1-o1-registration-native/run.py registration-parse
python3 .cinder/a1-o1-registration-native/run.py registration-native
```

Each invocation creates a new timestamp/UUID directory and refuses to reuse an existing directory. It retains command, queue timestamps, lifecycle, raw log, engine log, result, submitted/acquired/after source maps and, on a successful native job, a byte-exact copy and hash of the fixture's uniquely printed native report. Failures retain their original records. No old run is overwritten.

The completed session is pinned to `res://docs/development/evidence/act1-o1-integration/completed-return.native.json`, SHA-256 `2df0773bfbcd3a0fa22f907ae0df5502ef96c8f72966f33806299eee34efb79a`. Native arguments follow Godot's `--` separator as `--completed-session=...` and `--completed-sha256=...`. This checksum checks the supplied file; the original producer/receipt join remains Root's separate responsibility.

The 180-second validation deadline begins after the canonical `godot_lock` is acquired. The runner uses `dev.run_validation` without changing its process semantics. That API owns, terminates on deadline/error and waits for its direct validation child; it does not create or signal a separate process group. The runner neither signals another job, deletes a held lock nor launches a second engine outside the queue.

Source maps include the explicit fixture, inherited A1-O1 helper, actual O1/L2 scenes, shared Shell/Player/Level and their literal `res://` file-reference closure, registry, project, dev wrapper, runner and completed wire. Existing script/shader UID sidecars are named and required; no UID is manufactured. The maps are rechecked after queue acquisition and after closure. Changes while waiting refuse engine start; changes during a job fail its source stability result. Only the selected script UID's addition is allowed during import, and that addition is reported separately.

This is a selected source subset. JSON references are hash leaves, so the registry does not expand all 24 advertised levels. Implicit global class resolution, computed/directory loads, global UID/import metadata and whole evidence banks are outside the snapshot. Supported GD/project/shader line comments, generated `.cinder` paths and templates are excluded; the literal scanner is not a language parser and does not interpret shader block comments. The import command is the normal queued whole-project editor import and can change global engine metadata outside the named maps; unchanged selected sources do not establish a globally unchanged project. No copying of local settings or broad source/evidence banks occurs.

The runner supplies no level acceptance, inherited mechanics execution, route, GUI, visual, performance or campaign completion claim. Native report validation establishes only a completed zero-failure canonical registration fixture result. Root must join owner mechanics/visual evidence independently.
