# Fresh paused level restore construction

Candidate shared29 implements additive `level-restore-candidate-1`. It is not published until the targeted native constructor and directly affected Level/Shell checks close and the canonical mailbox names its exact commit. No level/source snapshot schema changes. Existing levels retain ordinary construction as the default.

Act1 request `df4cab4f-0809-4dfa-811a-a2e5ecb0b5d4` identified a genuine composition gap: a saved later room can have permanently bound recipients and installed fields while ordinary fresh entry contains dormant unbound sources and absent future fields. Pure validators cannot activate or bind them; commit cannot invent their native bindings. The new construction path runs before ordinary entry and before whole saved-state validation.

The actual Shell creates a hidden independent candidate world while the entire tree remains paused. `CinderLevel.enter_restore_candidate(player, effects, shell, saved_level, saved_player) -> bool` pins normal authored identity, checks the saved base envelope/progress/version and actual Player snapshot, then invokes `_on_enter_restore_candidate(local, saved_player) -> String`. It passes defensive copies only after those checks. The hook constructs the saved prefix's immutable native bindings; it does not apply saved HP, clocks, death, equipment, admission or history. Failure leaves a nonplayable entered candidate for normal exit cleanup and disposal.

An authored level that can change installed topology overrides the pure `restore_candidate_construction_required() -> bool` to return true. This makes even an earlier same-level Retry validate against its own fresh construction rather than the later active donor. Every submitted whole snapshot discards any older hidden validation candidate; an ID-only cache is insufficient. The exact newly validated candidate is reused for Player → level quiet commit. The live donor, checkpoint and disk are not reconstruction inputs to mutate.

`is_restore_candidate() -> bool` exposes the real paused candidate flag. An act-owned one-shot recipient constructor must verify that its actual retained ancestor is this candidate, that Hero/Scheduler aliases and native script/body/resources match, and that the recipient is genuinely pristine, configured and dormant. Preserve immutable `initially_dormant` configuration. Construct genuinely ready living binding recipients silently only for entitled installed rooms; do not call ordinary activation, emit callbacks, forge saved binding stamps, pretend dormant sources are alive, or seed role/profile/cycle/HP/hurt/sample history. Actual existing Protocol/Coordinator methods then bind those real ready sources and fields. A fresh unbegun Scheduler supports their pure initial control checks; there is no need to replay `begin_encounter` from saved data.

Installed source/field/consumer subsets derive from a closed saved prefix/stage and immutable authored tables. Future uninstalled fields remain absent; their future actors remain dormant and unbound. Validate every descriptor and alias before partial construction. Construction alone licenses neither play nor accepted saved state. The original native actor, field, Scheduler and consumer schemas/validators stay strict.

After complete pure aggregate prevalidation, the authored quiet commit restores Player, fields and native physical actors, Scheduler, native actor exchanges/stamps, consumers/routes and level progress/framing in their existing required order. It applies the true saved injured/dead/dormant state and original clocks; it never admits an attack, heals, refreshes supplies or emits events. `restore_state` marks the candidate ready only after successful validation/commit. `finish_restore_candidate() -> bool` releases the flag at Shell installation, before retiring the old world. Before that, all completion/checkpoint/contact-exit requests reject. An uncommitted candidate cannot become playable. Any construction, validation or commit failure disposes the fresh world and remains paused.

The default hook calls existing `_on_enter_level` for levels whose normal construction already suffices. Ordinary new-story/transition/replay entry still uses `enter_level`; existing accepted content does not require an owned migration merely because this method exists.
