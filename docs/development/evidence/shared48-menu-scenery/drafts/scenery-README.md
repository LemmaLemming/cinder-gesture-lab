## Native scale, pivot and rendering policy

One integer pixel grid:160×88Title;160×360route. Rendering uses integer uniform steps with centred integer origin, no stretch or antialias. At480×264Title it is3×, matching the existing144×192 display of the shared48×64 preview. Root minheight264 retains that scale;256height fits only2×/96×128 (still nearest, but smaller). At480×1080route it is3×, matching existing ACT_HEIGHT1080. Wider/taller sizes letterbox rather than stretching pixel proportions. A too-small Control draws nothing and returns an empty traveller rectangle; diagnostic grid.fits reportsfalse.

The preview rectangle is virtual(56,14,48,64), yielding the shared source feet pivot(24,64) at virtual(80,78). A low solid floor contact patch lies at the feet, not a hollow ring/available-target cue. Only CanvasItem drawing-command transforms are used; no node/camera/actor transform changes. Shapes are rasterized into whole virtual-cell rectangle runs, with broad tonal clusters, no uniform noise, pulse, timer, `_process`, physics, RNG, audio, shader, stream or scene load. Mouse filter IGNORE, focus NONE and clipping keep it noninteractive. Scenery is not an actionable prop, reward, hazard or authored collision/occluder. Reduced motion needs no branch because it is fully static. All quality modes retain the same static drawing.
